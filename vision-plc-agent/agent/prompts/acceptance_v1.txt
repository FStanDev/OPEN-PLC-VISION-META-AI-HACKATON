HOW THE HARNESS RUNS ONE TEST (your timings must fit this):
- t = 0 is the start of the test, times are ms from t = 0.
- First the harness plays the WHOLE stimulus list (each step presses or
  releases one button at its at_ms). Only after the last step does it check
  the expectations, one by one, in list order.
- Each expectation polls the PLC tag until it equals `value` (INT: within
  `tolerance`) or its deadline passes, then waits until the deadline and takes
  a camera frame. The tag AND the camera must show `value` AT the deadline.
- Deadline = `within_ms` ("becomes value by then") or `at_ms` ("is value at
  that time", e.g. after a timer expired). Give exactly one of them.
- So: every deadline at least 300 ms after the last stimulus step; deadlines
  never decrease down the expect list; pick each deadline in the middle of a
  window where the value is stable, at least 300 ms away from any change.
- A button press is a press step followed by a release step of the same
  button 200 ms later. Every press needs its release. Leave at least 500 ms
  between pressing different buttons.
- Tests run one after another on the same running PLC, with no restart in
  between. Each test must reach the state it checks with its own stimulus
  (e.g. press start first if it needs the running state) and must not end
  with a timer still running that a later test could see.
- While stop is held, all outputs are in the safe state. Anything the
  description wants "after stop" starts when stop is RELEASED.

- Every behaviour the description asks for. For a timed output, check it
